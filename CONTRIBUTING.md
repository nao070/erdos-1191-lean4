# Contributing

Contributions that improve navigation, reproduce a result, identify a mathematical gap, or clarify an experiment are welcome.

For a reproduction report, include the project path, revision, toolchain, exact command, and relevant output. For a mathematical correction, state the claim, hypotheses, and the specific step that fails or needs justification. Distinguish exact arithmetic and exhaustive finite checks from numerical approximations.

Keep changes focused. Preserve historical snapshots when adding a correction: explain what changes and which result it affects. Avoid promoting a conjecture or partial formalization to a proved result without a complete argument and appropriate verification.

For Lean changes, use the project's pinned toolchain and dependencies. Report whether the changed module builds, and include an axiom audit when relevant. Dataset-integrity checks and successful software execution are separate from mathematical correctness.
