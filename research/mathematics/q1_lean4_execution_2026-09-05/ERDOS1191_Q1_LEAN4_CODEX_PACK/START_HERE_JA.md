# Codexへの渡し方

**目的：Erdős Problem #1191 Q1の完全解決と、原命題に対応するLean 4の完全証明。** このパック自体は証明済み成果ではなく、その研究を実行させる指示・資料・検査補助です。

## 開始

ZIPを展開し、Codexで既存プロジェクト `erdos1191_PROOF_RESET_WORK_2026-08-29` を開きます。展開したパックを同プロジェクトから参照できる場所に置き、モデル選択は指定の **GPT-6 Astra Ultra** のままにします。PDFは人が読む説明用、実行時の主指示は `MASTER_PROMPT.md` です。PDFと同じ本文を何度もコンテキストに投入する必要はありません。

Codexに貼る文面：

> 添付／指定したパックの MASTER_PROMPT.md を読み、その指示に従って、既存プロジェクト上で Erdős Problem #1191 Q1 の研究と Lean 4 形式化を今すぐ実行してください。計画提示、有限計算の成功、補題の追加、障害の同定を完了扱いにせず、原Q1の完全証明または完全反証と、実際のLean検証まで進めてください。C143 V2のDownloads内runを一次資料として読み、古いC139台帳に戻らないでください。通常の技術的判断は自律的に行い、指定モデルと推論設定を下げないでください。

既に同じプロジェクトで作業中なら、そのスレッドでこの文面とパックの場所を渡して構いません。中断から再開するときは `RESUME_PROMPT.md` を使います。

## 成功条件

Q1の原命題またはその正しい否定を、一方に確定すること。人が追える数学的証明と、追加の未証明仮定に依存しないLean証明の両方が必要です。Leanの標準的な数学の公理は許可し、`sorryAx`、未証明の独自公理、命題のすり替え、外部計算の結果を無検証で信頼する仕組みは許可しません。[S2–S3]

障害を厳密に同定できても、それは次の研究課題です。利用可能な実行が続く間は、その障害または別経路への研究を続ける指示にしています。外部の実行上限・停止はプロンプトでは解除できないため、その場合だけ未完了の継続記録を残します。これは弱い成果への目標変更ではなく、偽の成功宣言を防ぐ扱いです。

## 実ファイルについて

138MBの `C143_BANK.json` とMac上の研究プロジェクト全体は、今回この環境には添付されていません。このZIPに含まれるのは、アップロードされた保存済みfull-pricing再検証JSON、4本の参考PDF、提示されたモデルガイド、指示書、対象命題仕様、検査補助です。Mac上のCodexは `LOCAL_INPUTS_REQUIRED.md` のパスから本物のrunを直接読んでください。

既存の `AGENTS.md` や研究ファイルを、このパックの名前に合わせて上書きする必要はありません。元runは読み取り専用に保ちます。

## 性能・設定

モデル表示名を尊重し、`gpt-6-astra-ultra` や `reasoning_effort=ultra` といった未確認のAPI設定を勝手に作りません。モデル名・推論設定を文章だけで変更できると仮定せず、Codexの実際の選択状態を維持します。数学経路、エージェント数、反復回数を過度に固定せず、原命題・証拠・成功条件を明確にしています。特定の文面が証明の成功率を保証するという測定結果はありません。

## パックの確認（任意）

パックのフォルダで実行：

```bash
python3 scripts/audit_inputs.py
python3 -m unittest discover -s tests -v
```

前者は保存報告の有理数区間・件数・スコープ等を検査します。90,600,510件のrootチェックを実行するものでも、Q1を証明するものでもありません。`--bank` に本物のバンクを指定すると、報告されたサイズとファイルハッシュも照合できます。

詳細は `C143_EVIDENCE_STATUS.md`、出典と検索上の制約は `RESEARCH_SOURCES.md` を参照してください。
